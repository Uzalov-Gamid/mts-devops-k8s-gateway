3. Ревью работы и масштабирование

Главная особенность. Решение не только разворачивается, но и доказывает свою работу: make verify проходит всю цепочку от запроса через Gateway до метрики в Prometheus и записи лога в Elasticsearch, make chaos показывает отсутствие ошибок при убийстве pod'ов, а SLO-алерты покрыты юнит-тестами. Всё это выполняется в CI на каждый PR.

Самое сложное решение. Выбор между Envoy Gateway, NGINX Gateway Fabric и Cilium Gateway. Выбрал Envoy Gateway: полная поддержка стандартного Gateway API, не требует особого CNI, отдаёт метрики Envoy для HTTP-кодов и latency из коробки.

Предложения по развитию.
  • Постоянные тома (PVC) и несколько реплик для Prometheus и Elasticsearch; ILM для логов (нужен StorageClass, например Longhorn или Ceph).
  • cert-manager и ACME/внутренний CA вместо самоподписанного сертификата (нужен DNS и внешний доступ для ACME либо корпоративный CA).
  • Alertmanager с уведомлениями (нужен канал: Telegram, e-mail), SLO по услугам абонентов.
  • NetworkPolicy и другой CNI (Calico или Cilium), Pod Security Admission в режиме restricted.
  • Высокая доступность control plane (3 ноды, kube-vip), MetalLB для LoadBalancer на bare metal.
  • GitOps (Argo CD или Flux) вместо запуска из Make, Argo Rollouts для canary.
  • Телеком-специфика: мониторинг SLA по задержке и доле 5xx для абонентских сервисов, ограничение скорости запросов (rate limit в Envoy) для API, мультикластер с несколькими регионами и разбор логов по абонентским идентификаторам с маскированием персональных данных.
